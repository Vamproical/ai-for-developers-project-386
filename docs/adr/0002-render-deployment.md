# Render deployment via Blueprint with two Docker web services

We deploy to Render as two public web services defined in a root `render.yaml` Blueprint — the Spring Boot jar and the nginx-served SPA — each built from its existing Dockerfile (`backend/Dockerfile`, `frontend/Dockerfile`) with `dockerContext: .` so the frontend build can emit and the backend build can compile the TypeSpec contract. The nginx proxy no longer targets the docker-compose hostname `backend`; it proxies same-origin API calls to `${BACKEND_PROTO}://${BACKEND_HOST}`, split into two env vars because Render's `fromService` reference only exposes `host` (no scheme) — the Blueprint sets `BACKEND_PROTO: https` and takes `BACKEND_HOST` from the backend service URL (`fromService.property: host`), keeping the SPA same-origin and avoiding CORS changes. We accepted the H2 in-memory database for now — every restart or redeploy wipes bookings, slots, and schedules — and deferred Postgres (driver already on the classpath) to a follow-up, trading durability for a first deploy that stays purely operational.
